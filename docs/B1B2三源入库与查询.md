## 数据与接口

`glyphs.db` 保留要求的 `id/char/calligrapher/style/dynasty/source_work/image_path/origin`，另有 `upstream_id/upstream_label/sha256/distributable`。有字符、字符+书家、origin 索引；`sources` 保存来源与使用边界，`character_aliases` 单独保存无歧义简繁标签别名。PNG 均为 256×256 RGBA、黑色墨迹、透明底、居中、四边至少 25px 留白。光栅底图以灰度反向生成 alpha；负碑拓仅以边角判断正反色，原图仍保存在 ZIP 中；SVG 用 resvg 以 96 DPI、1024px 超采样渲染再按墨迹 bbox 归一化。

数据库**保留上游的原字符标签**，不把孤立的“里/干/台”等强行改成某一个繁体字。查询先对整个输入做 OpenCC `s2t`，然后逐字查询；绝不二次逐字转换已转换的文本，以保留“千里”中的“里”。支持 `爲/為` 等 OpenCC `t2tw` 等价写法。无歧义简体类别（如“学”）可以作为“學”的标签别名；一简多繁的标签不自动推定字形身份。结果保留数据库字符、规范来源、origin、原始标签、绝对本地图路径；缺字返回空候选列表。多字查询应以外层 `characters[i].char` 配合候选 `path/source` 给 B5，避免把上游简体标签误当成已转换的正文。

覆盖分母：测试文本去标点后 81 个去重字符，按完整测试文本 `s2t`；常用字以 2013 一级字表 3,500 条逐条 `s2t`，报告保留原分母、去重数与字表 SHA256。字表来自 [原始转录仓库](https://github.com/shengdoushi/common-standard-chinese-characters-table)，该仓库链接国务院原 PDF；不使用 GB2312 的 3,755 字冒充 3,500 字。六家各自覆盖和联合缺字都有完整数组，联合缺字另附简体/繁体对照。

生成的 `docs/glyph_manifest_real.json` 保持：

```json
{
  "format": "glyph-manifest-v1",
  "local_only": true,
  "chars": {"海": {"颜真卿·多宝塔碑": "glyph_images/lushen/资源编号.png"}},
  "candidates": {"海": {"颜真卿·多宝塔碑": [{"id": 1, "path": "图路径", "origin": "lushen", "raw_char": "海", "upstream_id": "资源编号", "distributable": true}]}},
  "sources": {"颜真卿·多宝塔碑": {"calligrapher": "颜真卿", "source_work": "多宝塔碑", "origins": ["lushen"]}}
}
```

示例中的路径和 ID 是接口示意，不是额外伪造数据。`chars` 的值仍是 PNG 路径**字符串**；`candidates` 可保留同书家同作品多个字形和 origin，`sources/aliases` 为可选扩展，所有路径相对项目根目录。混合本地库使用 `glyph_manifest_real.json`；仅允许 origin 的资源视图另写 `glyph_manifest_distributable.json`。

原 `docs/glyph_manifest.json` 保持已验收的 81×4 占位库。B5 可以传 `manifestPath` 或查询返回的 `glyphs`；B4 的既有 `JiziService(manifestPath)` 能直接读取新库并切换来源，本轮没有修改 `layout.js` 和 `app/` 的代码。正式 GUI 启动仍使用已验收占位库；换默认数据入口留给后续验收，不偷偷替换安装版。同来源多字形在数据库/扩展中完整保留，既有 GUI 目前仅消费每个来源的首图，未在本轮增加同来源细分选择。
